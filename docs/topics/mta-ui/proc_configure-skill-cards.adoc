= Configure skill cards

[role="_abstract"]
To provide specific capabilities or tools to an agent, you can optionally configure skill cards. Agents can use skill cards in a single agent run or in a multi-stage workflow.

.Prerequisites

* Skills are available as an Open Container Initiative (OCI) image, in a Git repository, or a single `skill.md` Markdown file.

.Procedure

. Go to the *Skills* page in the *Agentic* section.
. Click *Create skill card*.
. Configure the skill card:
.. Enter a name for the skill card.
.. Optional: Enter a display name for the skill card.
.. Enter a description that is shown in the {ProductFullName} web console. The description field is the metadata displayed in the skill card details. 
+
The agent reads the description you provide in the `skill.md` file.
.. Select the type. The default option is `skill`. The agent reads only the name and description of a skill. When the agent decides that the skill is relevant for a task, {ProductShortName} loads the skill content for the agent. {ProductShortName} always loads rule for every prompt of every agent that refers to the rule type. Rules are part of the LLM context window.
.. Select one of *Inline*, *Image*, or *Git* as the skill source.
.. If you selected the inline source, paste the skill content inline.
.. If you selected image as the skill source, configure the following:
* The image URL
* The sub path that points to a specific skill
.. If you selected Git as the skill source, configure the following:
* The Git repository URL
* *Ref*: A branch, a tag, or a commit to check out from the Git source. If you leave this field empty, {ProductShortName} clones the default branch, which prevents the run from being reproducible.
* *Sub path*: The directory in the Git repository that contains the skill file
.. Optional: Configure the semantic version of the skill.
.. Optional: Configure tags for the skill card.
. Click *Create*.
