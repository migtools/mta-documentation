= Configure the LLM gateway secret 

[role="_abstract"]
To enable the agent to use a large language model (LLM) gateway, you must configure a Kubernetes secret that has an LLM API key in the Red Hat {ocp-name} project where you installed the {ProductShortName} Operator.

.Prerequisites

* You have an LLM API key.

.Procedure

. Create a credentials secret in the `openshift-mta` project.

.. For Amazon Bedrock as the provider, type:
+
[subs="+quotes"]
----
oc create secret generic bedrock-credentials -n openshift-mta \
  --from-literal=AWS_ACCESS_KEY_ID="<your-access-key-id>" \
  --from-literal=AWS_SECRET_ACCESS_KEY="<your-secret-access-key>" \
  --from-literal=AWS_REGION="us-east-1"
----
+

.. For Anthropic as the provider, type:
+
[subs="+quotes"]
----
oc create secret generic anthropic-credentials -n openshift-mta \
  --from-literal=api-key="<your-anthropic-api-key>"
----
+

.. For Google Vertex AI as the provider, type:
+
[subs="+quotes"]
----
oc create secret generic vertex-credentials -n openshift-mta \
  --from-file=GOOGLE_APPLICATION_CREDENTIALS_JSON="$HOME/.config/gcloud/application_default_credentials.json" \
  --from-literal=GCP_PROJECT_ID="$(gcloud config get-value project)" \
  --from-literal=GCP_LOCATION=global
----
+

.. For the OpenAI as the provider, type:
+

[subs="+quotes"]
----
oc create secret generic openai-credentials -n openshift-mta \
  --from-literal=api-key="<your-openai-api-key>"
----
+
.. For Grok as the provider, type:
+
[subs="+quotes"]
----
oc create secret generic grok-credentials -n openshift-mta \
  --from-literal=api-key="<your-xai-api-key>"
----
