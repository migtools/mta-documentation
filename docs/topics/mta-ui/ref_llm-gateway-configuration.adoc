= LLM gateway configuration

[role="_abstract"]
The large language model (LLM) gateways for agents are LLM provider-model pairs that you deploy as custom resources (CRs) in your cluster.

You can copy and edit the following sample LLM gateway configurations into a gateway YAML file:

.Example Google Vertex AI gateway 
[source,yaml]
----
apiVersion: konveyor.io/v1alpha1
kind: Gateway
metadata:
  name: gcp-vertex-ai
spec:
  provider: gcp-vertex-ai
  endpoint: "https://global-aiplatform.googleapis.com"
  credentialRef:
    secretName: vertex-credentials
  model:
    name: claude-sonnet-4-5@20250929
    contextWindow: 200000
    tier: premium
----
[NOTE]
====
Google Vertex AI gateway has no `credentialRef.key` field. When the key field is not set, the entire Secret is exposed to the sandboxed container with the Secret keys as variable names. This configuration is ideal for multi-variable credentials such as Google Cloud Platform Application Default Credentials (GCP ADC).
====

[source,yaml]
----
apiVersion: konveyor.io/v1alpha1
kind: Gateway

  name: aws-bedrock
spec:
  provider: aws-bedrock
  endpoint: "https://bedrock-runtime.us-east-1.amazonaws.com"
  credentialRef:
    secretName: bedrock-credentials
  model:
    name: us.anthropic.claude-sonnet-4-5-20250929-v1:0
    contextWindow: 200000
    tier: premium
----
[NOTE]
====
Amazon Bedrock gateway has no `credentialRef.key` field. When the key field is not set, the entire Secret is exposed to the sandboxed container with the Secret keys as variable names. This configuration is ideal for multi-variable credentials such as Amazon Web Services Signature Version 4 (AWS SigV4).
====
