Configuring repositories

To allow the {ProductFullName} access to the data required for the migration tasks, configure source and binary repositories in the user interface (UI).

You can configure the following repository types for the {ProductFullName} instance environment:

  • Git

  • Subversion

  • Maven

Enable insecure access to Git repositories

As an administrator, you can configure {ProductFullName} to accept self-signed or internal certificates to allow an insecure connection to your internal Git repository.

Procedure

  1. In Administration view, click Repositories and then click Git.

  2. Enable the Consume insecure Git repositories switch.

Enable insecure access to Subversion repositories

As an administrator, you can configure {ProductFullName} to accept self-signed or internal certificates to allow an insecure connection to your internal Subversion repository.

Procedure

  1. In Administration view, click Repositories and then click Subversion.

  2. Enable the Consume insecure Subversion repositories switch.

Enable insecure access to a Maven repository

As an dministrator, you can configure {ProductFullName} to accept self-signed or internal certificates to allow an insecure connection to access your Maven repository.

You can clear the Maven cache of your local artifact repository in the Repositories view of the {ProductShortName} web console to save disk space.

Important
 If you set the rwx_supported configuration field in the Tackle custom resource (CR) to false, {ProductShortName} disables both the Local artifact repository field and the Clear repository option. Therefore, you cannot clear Maven cache in following procedure.
Procedure

  1. In Administration view, click Repositories and then click Maven.

  2. Enable the Consume insecure artifact repositories switch.

  3. Optional: To reduce the size of the local Maven artifacts, click the Clear repository link.

    Note
    		 Depending on the size of the Maven repository, the size change might not be evident.
