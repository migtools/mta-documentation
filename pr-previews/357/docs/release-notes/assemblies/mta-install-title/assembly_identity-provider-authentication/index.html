Identity provider authentication

As an administrator, you can simplify security and regulatory compliance by implementing the {ProductFullName} Hub as an OpenID Connect (OIDC) broker to federate user authentication to an identity provider (IdP).

You can integrate the following IdPs and managing roles:

  • Keycloak

  • Microsoft Entra ID (formerly, Azure Active Directory)

  • Google

  • Okta

Create a secret for the IdP client

If you configured a secret in the Identity Provider (IdP) client configuration, enable the {ProductFullName} Hub to use the secret to connect to the Identity Provider (IdP) client.

Prerequisites

  • You installed {ProductShortName} {ProductVersion} in an OpenShift cluster.

  • You have admin access to the cluster.

  • You configured a secret in the IdP configuration for a secure connection.

Procedure

  1. Create a secret such as <idp-client-secret>.yaml:

    apiVersion: v1
kind: Secret
metadata:
  name: idp-client-secret
  namespace: <mta-namespace>
type: Opaque
stringData:
  clientSecret: "<secret>"

    • <mta-namespace>:: The namespace where you deployed {ProductShortName}.

    • <secret>:: The secret that you configured in the identity provider configuration.

  2. Apply the <idp-client-secret>.yaml file in the cluster:

    $ oc apply -f <idp-client-secret>.yaml

  3. Restart the Hub to load the secret:

    $ oc rollout restart deployment/tackle-hub -n openshift-mta

Configure an identity provider custom resource

To enable the {ProductFullName} Hub OpenID Connect (OIDC) provider to integrate with an identity provider (IdP), create an IdentityProvider custom resource (CR).

Prerequisites

  • You have installed the {ProductShortName} {ProductVersion} application in a Red Hat OpenShift cluster.

  • You have admin access to the cluster.

  • Optionally, you have created a secret for the IdP.

Procedure

  1. Create an <my-idp>.yaml custom resource:

    apiVersion: tackle.konveyor.io/v1alpha1
kind: IdentityProvider
metadata:
  name: corporate-sso
  namespace: openshift-mta
spec:
  name: "Corporate SSO"
  issuer: "https://idp.example.com/realms/tackle"
  clientId: "my-client-id"
  clientSecret:
    name: idp-client-secret
    namespace: openshift-mta
  redirectURI: "https://hub.example.com/oidc/idp/callback"
  primary: true
  scopes:
    - openid
    - profile
    - email

    • name:: Specifies the display name for the IdP button in the UI.

    • issuer:: Specifies the IdP issuer URL for OIDC discovery. You can use template variables in the issuer field. For example, "${issuer.proto}://${issuer.host}/auth/realms/tackle".

    • clientId:: Specifies the OAuth client ID that is registered with the IdP.

    • clientSecret:: Specifies an optional Kubernetes secret for the {ProductShortName} Hub to securely connect to the IdP. Omit this configuration if you did not create a secret for the IdP.

    • redirectURI:: Specifies the callback uniform resource identifier (URI) to the {ProductShortName} Hub after the IdP authentication completes. You must add the /oidc/idp/callback path to the Hub URI. You can use template variables in the redirect URI field. For example, "${issuer.proto}://${issuer.host}/oidc/idp/callback".

    • primary:: Specifies whether the IdP is the primary authentication method. When true, the Hub redirects users automatically to this IdP for authentication. If you configured the idp_primary field in the Tackle CR, the {ProductShortName} Hub resolves the configuration for this field from the Tackle CR value.

    • scopes:: Specifies the OAuth scopes that are used by an OpenID Connect client to request the access privileges for the access token.

  2. Apply the `<my-idp>.yaml file in the cluster:

    $ oc apply -f <my-idp>.yaml

  3. Restart the Hub to load the configuration:

    $ oc rollout restart deployment/tackle-hub -n openshift-mta
