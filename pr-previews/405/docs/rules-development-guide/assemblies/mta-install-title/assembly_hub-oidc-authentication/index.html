Authentication and Authorization

To authenticate users in the {ProductFullName}, you can use the Hub OpenID Connect (OIDC) provider to reduce infrastructure management or integrate {ProductShortName} with any OIDC provider.

Why use the Hub OIDC

The {ProductFullName} Hub implements an OpenID Connect (OIDC) standards-compliant provider that offers local user authentication and federation to other providers.

The {ProductShortName} Hub OIDC provider offers the following advantages:

  • An option to remove the Keycloak dependency for configuring users, roles, and permissions. Without Keycloak, you need not provision and manage extra infrastructure resources.

  • Simplified role-based access control (RBAC) deployment that allows you to manage users, default and custom roles, and permissions in the {ProductShortName} application.

  • An option to integrate Lightweight Directory Access Protocol (LDAP) or federate to another identity provider (IdP).

  • A permanent list of immutable permissions that map to specific application programming interface (API) resources and operations. This list ensures that authorization works consistently across deployments and simplifies security audits.

  • Tasks and add-on access to the {ProductShortName} APIs through personal access tokens (PATs) with fine-grained permissions.

Administrative tasks

As an administrator, you can configure user authentication and manage users, roles, and tokens to customize your environment.

You can use one of the following authentication flows with the {ProductShortName} Hub OpenID Connect (OIDC):

Local authentication and authorization

You can add users and link roles to them in the {ProductShortName} application without any extra configuration.

Lightweight Directory Access Protocol (LDAP)-backed authentication

Configure an LdapProvider custom resource (CR) to integrate LDAP users. Optionally, configure and deploy secrets in your Red Hat OpenShift cluster for a secure connection with the LDAP client.

Federated authentication to Identity Providers (IdPs)

Configure the IdentityProvider CR to federate authentication to an IdP such as Google, Okta, Keycloak, or Microsoft Entra ID (formerly, Azure Active Directory). Optionally, configure and deploy secrets in your Red Hat OpenShift cluster for a secure connection with the IdP client.

To migrate Keycloak that you implemented in earlier versions after an {ProductShortName} {ProductVersion} upgrade, see Keycloak migration.

Optional configurations

You can complete the following optional configure tasks:

  • Configure authentication and token variables in the Tackle custom resource (CR).

  • Create custom roles.

  • Create and revoke application programming interface (API) keys.

Enable authentication in Tackle custom resource

As an administrator, you can configure authentication fields and the token lifespan in the Tackle custom resource (CR). If you do not configure these fields, the {ProductFullName} Hub applies default values.

Prerequisites

  • You deployed a Red Hat OpenShift cluster.

  • You installed {ProductShortName} {ProductVersion} in the cluster.

Procedure

  1. Edit the tackle CR:

    $ oc edit tackle

  2. Switch to the edit mode in the terminal text editor:

    i

  3. Optionally, configure the authentication fields:

    spec:
  feature_auth_required:true
  idp_primary:true
  hub_oidc_token_lifespan:300
  hub_oidc_refresh_token_lifespan:172800
  hub_apikey_lifespan:87600
  hub_auth_cache_lifespan:5
  hub_ldap_auth_lifespan:5
  hub_oidc_key_rotation:90

    • feature_auth_required:: Specifies whether to enforce authentication to the Hub API and the web console. By default, the value is true.

    • idp_primary:: Specifies whether {ProductShortName} Hub automatically redirects authentication to the auto-discovered Keycloak identity provider in upgraded deployments. When this value is true in other deployments, the Hub redirects to the IdP automatically.

      When false, users can authenticate on the {ProductShortName} login page. If you configured an identity provider (IdP), then users can authenticate by using the IdP button on the login page.

    • hub_oidc_token_lifespan:: Specifies the OAuth access token lifespan. The default value is 300 seconds.

    • hub_oidc_refresh_token_lifespan:: Specifies the OAuth refresh token lifespan. The default value is 172800 seconds (2 days).

    • hub_apikey_lifespan:: Specifies the OAuth API key lifespan. The default value is 87600 hours.

    • hub_auth_cache_lifespan:: Specifies the OAuth authentication cache lifespan. The default lifespan is 5 minutes.

    • hub_ldap_auth_lifespan:: Specifies the LDAP authentication lifespan. The default lifespan is 5 minutes.

    • hub_oidc_key_rotation:: Specifies the OIDC key rotation interval. The default value is 90 days.

  4. Save the changes and exit the text editor to apply the changes:

    :wq!
